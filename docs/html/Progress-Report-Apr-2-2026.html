Progress Report - April 2, 2026

Overfitting remediation update: what changed, updated metrics, and current interpretation.

Project: Order-Time Backorder Modeling (v2)

Focus: Reduce validation inflation and improve forward-test realism.

Source baseline: docs/html/Progress-Report-Mar-28-2026-v2-ordertime.html

What was changed to reduce overfitting

  • Leakage controls: removed delivery, billing, inventory snapshot, outstanding, aging, and backorder-derived fields from model input.
  • Label cleanup: unresolved outcomes excluded so missing fulfillment does not act as a target proxy.
  • Grain contract: enforced one row per client_id + sales_document_number + item_number to prevent one-to-many expansion leakage.
  • Temporal policy: calendar holdout with minimum positive support replaced unstable tail slicing.
  • Pipeline governance: notebooks now consume production artifacts instead of generating competing model outputs.

Short interpretation

Primary readout: grouped scores dropped after leakage removal (expected), while temporal performance improved from a collapsed baseline to a usable signal.
Remaining constraint: temporal performance is still limited by sparse positives and late-period drift, so threshold calibration and temporal stress tests remain active work.
